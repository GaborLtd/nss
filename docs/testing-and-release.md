# Testing, CI, and Release Process

## Feature definition of done

Before a feature is considered complete, it must have:

1. Behavior documentation or a protocol/lifecycle update.
2. Unit tests.
3. An integration test when needed, such as a local SSH/PTY fixture.
4. Passing local checks and GitHub Actions CI.
5. An updated README or release notes for user-visible changes.

## Local validation

```bash
gofmt -w .
go vet ./...
go test -race -cover ./...
go build ./cmd/nss ./cmd/nssd
```

Before a release, use a GoReleaser snapshot:

```bash
goreleaser release --snapshot --clean
```

## CI

`.github/workflows/ci.yml` runs on pull requests, pushes to the main branch, and manual dispatch:

- gofmt check
- `go vet`
- race-enabled tests
- coverage-enabled tests
- `nss` and `nssd` builds

CI requires only `contents: read`.

## Versioning

Use Semantic Versioning:

```text
vMAJOR.MINOR.PATCH
```

- MAJOR: incompatible protocol, CLI, or session semantics.
- MINOR: backward-compatible features.
- PATCH: bug fixes, documentation, and non-behavioral corrections.

## Release process

1. Confirm that CI passes on the main branch.
2. Update the changelog and any required migration documentation.
3. Create and push an annotated tag:

   ```bash
   git tag -a v0.1.0 -m "nss v0.1.0"
   git push origin v0.1.0
   ```

4. GitHub Actions triggers GoReleaser.
5. GoReleaser creates the GitHub Release and artifacts:
   - `nss_<version>_<os>_<arch>.tar.gz`
   - `checksums.txt`
6. Verify the GitHub Release assets and checksum.
7. Validate the installer:

   ```bash
   NSS_REPOSITORY=gaborltd/nss NSS_VERSION=v0.1.0 sh scripts/nss_install.sh
   ```

8. Use the GitHub raw URL initially; point `/nss_install.sh` to the same script after a custom domain is available.

## Manual reconnect validation

Start `nssd serve` on a test server and confirm that `nssd` is in the SSH login shell's `PATH`. From a native terminal, run:

```bash
nss office-mini
```

Run a non-immediate job such as `sleep 120`, temporarily interrupt the laptop network, and confirm that the tab stays open. After connectivity returns, it should return to the same shell. Do not enter data-changing commands during the test, and confirm that disconnected input was not replayed.

### Service registration manual test

In a temporary user environment on macOS or Linux, run:

```bash
nssd service status
nssd service install
nssd service status
nssd service restart
nssd service uninstall
nssd service status
```

Confirm that the installed service file uses an absolute `nssd` path, status can report active, and uninstall reports not-installed. Do not use root or delete a service file not generated by nss.

The GitHub Actions release job runs only after the tag build passes and uses the minimum `contents: write` permission to create the release. Token permissions must be declared explicitly rather than relying on repository defaults.

## Installer contract

The installer must:

- Support macOS/Linux.
- Support amd64/arm64.
- Install to `~/.local/bin` by default.
- Allow `NSS_INSTALL_DIR` to override the destination.
- Allow `NSS_VERSION` to select a specific version.
- Allow `NSS_REPOSITORY` to select a GitHub repository.
- Resolve the latest version through the GitHub Releases redirect when `NSS_VERSION` is unset; do not depend on the Releases API.
- Verify SHA-256 after downloading.
- Avoid root and do not modify shell profiles automatically.
- Tell the user to verify that the install directory is on `PATH`.
